<!-- sdlc:auto:start overview -->
MediBook is a doctor appointment and consultation management application generated by the Quorq AI SDLC platform, kept as two applications in one repository. `frontend/` is a Vite + React 19 single-page app (TypeScript, Tailwind v4, React Router 7, TanStack Query, react-hook-form) whose screens live one-per-module under `src/screens/` with a shared UI/icon/brand vocabulary in `src/lib/`; most screens still render seeded sample data, and `src/lib/api.ts` is the seam for wiring them to the real API. `backend/` is a FastAPI service using SQLAlchemy 2 ORM models and Pydantic v2 schemas, with routers for public authentication (register/login/logout/me, opaque bearer tokens whose hashes are stored in a `sessions` table), admin-only user management, and ownership-guarded clinical read endpoints that currently refuse every id because appointment/consultation storage has not been built yet. The database defaults to a local SQLite file via `DATABASE_URL`, with Postgres 16 and Redis 7 available through `docker-compose.yml`; tables are created from the models at startup (no migrations) and startup seeding runs from `app/seed.py`. Deployment is a GitHub Actions workflow that builds the backend Docker image and publishes the frontend bundle to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start setup -->
1. Clone the repository and open it in your editor (a .devcontainer/devcontainer.json is provided if you prefer a container).
2. Copy the example environment file: cp .env.example .env (see ENVIRONMENT.md for what each variable means).
3. Backend: cd backend && python -m venv .venv && source .venv/bin/activate
4. Install backend dependencies: pip install -r requirements.txt
5. Start the API (defaults to a local SQLite database at ./app.db, so no database server is required): uvicorn app.main:app --reload
6. Optional — to run against Postgres/Redis instead, start them with: docker compose up -d   then export DATABASE_URL="postgresql+psycopg://<db-user>:<database-password>@localhost:5432/<db-name>" before starting uvicorn.
7. Frontend: in a second terminal, cd frontend && npm install
8. Start the SPA dev server: npm run dev (it reads VITE_API_BASE_URL, falling back to http://localhost:8000).
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routers are one module per architecture component under app/routers/, each exporting a `router` via __all__ and mounted in main.py with a path prefix and tags (/api/auth, /api/admin, /api/ for clinical).
- Request/response shapes are Pydantic models in app/schemas.py; read models never contain password fields, and AliasChoices lets endpoints accept both the contract field name (initial_password/new_password) and `password`.
- Validation failures return 422 as {"detail": [{"field", "msg"}]} — both from the global RequestValidationError handler and from hand-rolled checks in routers.
- 403/404 responses that must not leak existence are raised as EmptyBodyHTTPError and returned with no body, so a missing record and a forbidden one are indistinguishable.
- Authentication uses opaque bearer tokens; only a hash is stored in the sessions table, passwords are bcrypt hashes, and FastAPI dependencies (`current_user`, `require_role(...)`, `authorize_ownership`) enforce access.
- Database access is through a request-scoped session dependency (`get_db`); DATABASE_URL drives SQLite locally and Postgres (with the citext extension) in deployment. Schema is created from models at startup — there are no migrations yet.
- Frontend uses the `@/` path alias for `src/`, React function components in PascalCase files, and route guards composed with `RequireRole` inside `AuthProvider` in App.tsx.
- All HTTP calls go through `apiRequest`/`apiFetch` in src/lib/api.ts, which attaches the stored session token (falling back to the build-time secret), throws `ApiError` for non-2xx responses, and invokes a registered handler on 401.
- Vitest component tests sit beside the component they cover (`*.test.tsx` under src/), while Playwright `*.spec.ts` files live in e2e/ so the two runners never collect each other's files.
- Styling uses Tailwind utilities plus CSS variables from the approved brand tokens (var(--brand-*)).

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails with `ModuleNotFoundError: No module named 'app'`. | Run pytest from the backend/ directory — pytest.ini sets `pythonpath = .` relative to that folder, and make sure your virtualenv with requirements.txt installed is active. |
| Browser calls from the SPA are blocked by CORS. | main.py allows localhost/127.0.0.1 on ports 5173 and 4173 by default. If you serve the frontend from another origin, set ALLOWED_ORIGINS (comma separated) on the backend process before starting uvicorn. |
| The app starts fine locally but fails against Postgres with an error about CITEXT. | Startup issues `CREATE EXTENSION IF NOT EXISTS citext` for the postgresql dialect, so the DATABASE_URL user needs permission to create extensions; otherwise create the extension in the database first. |
| The API returns 500 on every authenticated request, or refuses to start. | SESSION_IDLE_MINUTES is validated at startup by validate_session_idle_minutes(); check the startup log and correct the value in your environment. |
| `npm run test:e2e` fails because the backend web server never becomes healthy. | The Playwright webServer runs `backend/.venv/bin/python -m uvicorn app.main:app`. Create that virtualenv first: cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt — or set E2E_BASE_URL to run against an already-running deployment. |
| `npm run build` succeeds but deployment or CI fails on TypeScript errors. | vite build does not typecheck. Run `npm run typecheck` (tsc --noEmit) and fix the reported errors — commonly untyped useState({}) later read for named fields. |
| GET /api/appointments/{id} and /api/consultations/{id} always return 403 with an empty body. | That is expected today: no appointment or consultation tables exist yet, so the ownership guard resolves no owner. The routers note where to supply the looked-up record's owner id once storage lands. |
| A screen shows sample data instead of API data. | The generated screens still run on seeded sample data by design; wire a screen to the backend through apiFetch/apiRequest in src/lib/api.ts and set VITE_API_BASE_URL to the API origin. |
| Port 5432 or 6379 is already in use when running docker compose up. | Stop the conflicting local Postgres/Redis, or change the published port mappings in docker-compose.yml and update DATABASE_URL accordingly. |
<!-- sdlc:auto:end troubleshooting -->
