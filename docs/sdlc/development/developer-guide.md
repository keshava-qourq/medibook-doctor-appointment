<!-- sdlc:auto:start overview -->
MediBook is a two-application monorepo generated by the Quorq AI SDLC platform for a doctor appointment and consultation management product. `frontend/` is a Vite + React 19 single-page app (TypeScript, React Router 7, TanStack Query, Tailwind 4) whose approved screens — sign-in, registration, find-a-doctor, doctor profile/schedule/availability, patient profile and an admin console — are route-guarded by role and still largely render seeded sample data, with `src/lib/api.ts` as the seam for real API calls. `backend/` is a FastAPI service (SQLAlchemy 2, Pydantic 2) that already implements session-token authentication (bcrypt hashes, opaque bearer tokens stored only as hashes), admin user management, patient self-service profile, medical specializations and a disease/symptom catalogue with deterministic term-driven doctor search, clinic settings, and ownership-guarded appointment/consultation read stubs. It creates its schema and seeds catalogue/startup data on startup, defaults to a local SQLite file so a fresh clone runs with no database server, and points at PostgreSQL via `DATABASE_URL`; `docker-compose.yml` provides Postgres 16 and Redis 7 for that, and a GitHub Actions workflow builds the backend image and publishes the frontend bundle.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+ and npm (Vite 6 / React 19 toolchain)
- Python 3.12 (the backend image is built on python:3.12-slim)
- pip and optionally venv for an isolated backend environment
- Docker + Docker Compose (optional — only needed for the PostgreSQL and Redis services in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. git clone the repository and cd into it
2. cd backend && python -m venv .venv && source .venv/bin/activate
3. pip install -r requirements.txt
4. uvicorn app.main:app --reload   # starts on http://127.0.0.1:8000, creates tables and seeds data on startup (SQLite ./app.db by default)
5. In a second shell: cd frontend && npm install
6. npm run dev   # Vite dev server; the API client defaults to http://localhost:8000 unless VITE_API_BASE_URL is set
7. Optional, to run against PostgreSQL/Redis instead of SQLite: docker compose up -d, then start the backend with DATABASE_URL pointing at the compose database (see .env.example / ENVIRONMENT.md for the exact variable names and use a placeholder such as <database-password>)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend is layered: routers/ hold HTTP concerns, models.py holds SQLAlchemy models, schemas.py holds Pydantic request/response pairs, security.py holds hashing and session issuance.
- One router module per architecture component; routers that have both a public and an admin surface export `public_router` and `admin_router` (admin routers carry a router-level `Depends(require_role("admin"))`).
- API paths are namespaced under /api, with admin endpoints under /api/admin; /health sits at the root.
- Validation errors are normalised to 422 `{"detail": [{"field", "msg"}]}` by a global RequestValidationError handler; 403/404 responses that must not leak existence are raised as EmptyBodyHTTPError and returned with no body.
- Identity always comes from the verified bearer token (never the request body); only bcrypt hashes of passwords and hashes of session tokens are stored.
- Destructive admin actions prefer soft state changes: specializations deactivate rather than hard-delete when referenced, catalogue terms are soft-deleted via `is_deleted`, and seeded rows keep a stable `seed_key` so seeding is idempotent.
- Case-insensitive text uses a CIText type decorator (CITEXT on Postgres, String elsewhere) plus `func.lower(...)` comparisons so behaviour matches on SQLite.
- Schema is created from the models in the FastAPI lifespan (no migrations yet) — Alembic is explicitly flagged as the replacement before real data is held.
- Frontend uses the `@/` path alias for `src/`, one module per screen in `src/screens/`, Vitest component tests colocated as `*.test.tsx`, and Playwright `*.spec.ts` kept out of Vitest's include glob.
- Routing is role-guarded via `RequireRole` wrappers in App.tsx; brand values live as tokens in `src/lib/brand.ts` and CSS variables in `src/index.css`.
- All runtime configuration comes from environment variables (DATABASE_URL, ALLOWED_ORIGINS, SESSION_IDLE_MINUTES on the backend; VITE_-prefixed variables inlined at build time on the frontend).
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails with `ModuleNotFoundError: No module named 'app'`. | Run pytest from the backend/ directory — pytest.ini sets `pythonpath = .` relative to that folder. |
| Browser calls from the SPA are blocked by CORS. | The backend allows localhost/127.0.0.1 on ports 5173 and 4173 by default; for any other origin set ALLOWED_ORIGINS (comma-separated) before starting uvicorn. |
| The frontend calls localhost in a deployed build. | VITE_API_BASE_URL is inlined at build time (src/lib/api.ts falls back to http://localhost:8000). Set it before `npm run build`, not at runtime. |
| The app starts but writes to a local SQLite file instead of PostgreSQL. | database.py defaults DATABASE_URL to sqlite:///./app.db. Export DATABASE_URL with your Postgres connection string (keep the password as a placeholder such as <database-password> in docs) before starting uvicorn. |
| The app fails at startup complaining about the session idle setting. | SESSION_IDLE_MINUTES is validated in the lifespan hook so a bad value fails loudly at boot — correct the value (see ENVIRONMENT.md / .env.example) and restart. |
| `npm run build` succeeds but deployment-time typechecking fails. | vite build does not typecheck. Run `npm run typecheck` (tsc --noEmit) and fix the reported errors. |
| Playwright fails to start the backend web server. | The config runs `backend/.venv/bin/python -m uvicorn ...`, so create backend/.venv and install requirements.txt into it first, or set E2E_BASE_URL to run against an already-running deployment. |
| Playwright Chromium crashes in a container. | The config already passes --disable-dev-shm-usage; if it still crashes, give the container more /dev/shm or run with fewer workers (the config pins workers to 1). |
| docker compose fails because port 5432 or 6379 is already bound. | Stop the local PostgreSQL/Redis instance or change the published port mapping in docker-compose.yml. |
<!-- sdlc:auto:end troubleshooting -->
