<!-- sdlc:auto:start overview -->
MediBook is a doctor appointment and consultation management system generated by the Quorq AI SDLC platform as a two-app monorepo. The frontend/ is a Vite + React 19 single-page app (with React Router, TanStack Query, React Hook Form and Tailwind) whose approved screens currently render seeded sample data; wiring them to the real API is still pending. The backend/ is a FastAPI service using SQLAlchemy 2.x and Pydantic 2.x, with authentication (register/login/logout/me) and admin user management implemented; many other routes are typed stubs. It defaults to a local SQLite database but can point at PostgreSQL via DATABASE_URL, and ships a Dockerfile plus a docker-compose.yml with Postgres 16 and Redis.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (supporting Vite 6 / React 19) with npm
- Python 3.12 (the backend Dockerfile uses python:3.12-slim)
- Docker and Docker Compose (optional, for the Postgres/Redis services)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository and open two terminals, one for frontend/ and one for backend/.
2. Frontend: cd frontend && npm install
3. Frontend: npm run dev (starts the Vite dev server)
4. Backend: cd backend && pip install -r requirements.txt
5. Backend: uvicorn app.main:app --reload (starts the FastAPI service; defaults to a local SQLite database at ./app.db)
6. Optional: from the repo root run docker compose up -d to start the Postgres 16 and Redis 7 services defined in docker-compose.yml, then set DATABASE_URL for the backend to use Postgres.
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend architecture: one router per component, one route per endpoint; unimplemented routes return a typed StubResponse so the service starts and its OpenAPI is complete.
- Role-based access with three roles (patient, doctor, admin); FastAPI dependencies enforce require_role, and the frontend guards routes via RequireRole.
- Passwords are stored only as bcrypt hashes; sessions store only a hash of the opaque bearer token, which is returned once at issuance.
- Database is SQLite by default via DATABASE_URL; tables are created from models at startup (no migrations shipped — replace with Alembic before storing real data).
- Email uniqueness is case-insensitive (CITEXT on Postgres, plain text elsewhere).
- Validation errors return 422 with per-field detail; certain 403/404 responses carry no body (EmptyBodyHTTPError).
- Frontend tests live beside the components they cover; Vitest is scoped to src/ while Playwright owns e2e/.
- API client throws ApiError for non-2xx responses and sends a bearer token (session token, falling back to the shared secret).
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| npm run build succeeds but deployment fails on type errors. | vite build does not typecheck; run npm run typecheck (tsc --noEmit) and fix errors such as untyped useState before deploying. |
| Running pytest from backend/ cannot import app. | Run pytest from the backend/ directory; pytest.ini sets pythonpath = . so the app package resolves. |
| Playwright specs get collected by Vitest and fail. | Vitest is scoped to src/ in vite.config.ts; run Playwright specs with npm run test:e2e instead. |
| Browser calls to the API are blocked by CORS in development. | The backend allows localhost:5173/127.0.0.1:5173 by default; set ALLOWED_ORIGINS (comma-separated) to your frontend origin when deployed. |
| Backend startup fails when DATABASE_URL points at a server that is not up. | Leave DATABASE_URL unset to use the default local SQLite database, or start the Postgres service via docker compose up -d before setting DATABASE_URL. |
