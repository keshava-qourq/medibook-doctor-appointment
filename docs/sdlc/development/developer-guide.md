<!-- sdlc:auto:start overview -->
MediBook is a doctor appointment and consultation management system generated by the Quorq AI SDLC platform, living in one repository with two applications. The frontend (frontend/) is a Vite + React 19 single-page app using React Router, TanStack Query, react-hook-form and Tailwind, with one module per approved screen; it currently renders seeded sample data and exposes a shared API client (src/lib/api.ts) as the seam to wire real calls. The backend (backend/) is a FastAPI 0.115 service backed by SQLAlchemy 2.0, defaulting to SQLite locally and targeting PostgreSQL 16 in deployment, with routers per component for auth, admin user management, appointments, availability, doctor directory, patient self-service, search, settings and specializations. It uses opaque bearer-token sessions, bcrypt password hashing, role-based access (patient/doctor/admin), and a deterministic disease/symptom-to-specialization catalogue lookup (no AI/ML). The schema is created from models at startup and seeded idempotently.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for the Vite + React 19 frontend; npm)
- Python 3.12 (backend Dockerfile uses python:3.12-slim)
- Docker and Docker Compose (optional, for PostgreSQL 16 and Redis via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository.
2. Frontend: cd frontend
3. npm install
4. npm run dev
5. Backend (in a separate terminal): cd backend
6. pip install -r requirements.txt
7. uvicorn app.main:app --reload
8. Optional: from the repo root run 'docker compose up -d' to start PostgreSQL 16 and Redis, then point the backend at it with DATABASE_URL (the backend defaults to SQLite at sqlite:///./app.db when DATABASE_URL is unset).
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component that owns endpoints, each wired into app.main; API paths are prefixed under /api (with /api/admin for admin-only surfaces).
- Role-based access via require_role/current_user dependencies; identity is always taken from the verified bearer token, never the request body.
- Ownership-guarded reads return 403 (or 404) with an empty body so missing and forbidden cases are indistinguishable (EmptyBodyHTTPError).
- Pydantic schemas come in request/response pairs per entity; passwords are never returned by read endpoints and are stored only as bcrypt hashes.
- Soft-delete / soft-deactivate (is_active, profile_active, is_deleted) is preferred over hard deletion to preserve appointment history.
- Database defaults to SQLite for a zero-setup local run; DATABASE_URL switches to PostgreSQL with no other changes. Schema is created from models at startup (no migrations shipped).
- Case-insensitive email via a CIText type (CITEXT on Postgres, plain text elsewhere).
- Frontend: one module per approved screen under src/screens, route table in App.tsx, route guards via RequireRole; screens currently render seeded sample data and api.ts is the seam for real calls.
- Frontend tests live beside the components they cover (Vitest); Playwright specs live in e2e/.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend API calls go to localhost after deployment. | VITE_API_BASE_URL is baked in at build time; set it (and VITE_API_SECRET_KEY as needed) before building so the bundle points at the deployed API. Unset, it falls back to http://localhost:8000. |
| Backend returns 500 on every authenticated request at startup. | A bad SESSION_IDLE_MINUTES is rejected at startup by validate_session_idle_minutes; set a valid value so the service starts cleanly. |
| Browser blocks API calls with a CORS error. | Add the SPA origin to ALLOWED_ORIGINS (comma-separated) for the backend; by default it allows the local Vite/preview origins (5173/4173). |
| Running uvicorn against PostgreSQL fails to connect. | Ensure the database is up (e.g. docker compose up -d) and DATABASE_URL points at it; the backend creates the citext extension and tables on startup. Leave DATABASE_URL unset to use the default SQLite file for a zero-dependency run. |
| `pytest` cannot import app. | Run pytest from the backend/ directory; pytest.ini sets pythonpath=. so a bare `pytest` can import the app package. |
| Playwright specs are picked up by Vitest and fail. | Vitest is scoped to src/ in vite.config.ts; run e2e specs via `npm run test:e2e` so Playwright owns the e2e/ folder. |
<!-- sdlc:auto:end troubleshooting -->
