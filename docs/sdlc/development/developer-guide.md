<!-- sdlc:auto:start overview -->
MediBook is a doctor appointment and consultation management system generated by the Quorq AI SDLC platform, living in one repository with two applications. The frontend is a Vite + React 19 single-page app (using react-router-dom) whose approved screens currently run on seeded sample data. The backend is a FastAPI service (FastAPI 0.115, SQLAlchemy 2, Pydantic 2) that is a scaffold: it exposes only a /health endpoint, creates tables from (currently empty) models at startup, and defaults to a local SQLite database. A docker-compose file provides PostgreSQL 16 and Redis for local infrastructure, and a GitHub Actions workflow deploys the image to AWS (ECR + Amplify).
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for Vite 6 / React 19; npm)
- Python 3.12 (backend Dockerfile uses python:3.12-slim)
- pip
- Docker and Docker Compose (optional, for Postgres 16 and Redis via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository.
2. Frontend: cd frontend && npm install
3. Start the frontend dev server: npm run dev
4. Backend (in a separate shell): cd backend && pip install -r requirements.txt
5. Start the backend: uvicorn app.main:app --reload (defaults to a local SQLite database at sqlite:///./app.db)
6. Optional: from the repo root, run docker compose up to start PostgreSQL 16 and Redis, then point the backend at it by setting DATABASE_URL.
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend uses path alias '@/' mapped to './src' (vite.config.ts and tsconfig.json).
- Routing is centralized in src/App.tsx; screens live one-per-module in src/screens/.
- Component tests live beside the components they cover (src/**/*.{test,spec}); Playwright specs stay in e2e/.
- Backend models inherit from the shared Base; main.py imports models before Base.metadata.create_all.
- Each API route returns a typed StubResponse placeholder until implemented, keeping the service startable and its OpenAPI document complete.
- Backend reads configuration from environment variables (DATABASE_URL, ALLOWED_ORIGINS) with safe local defaults.
- The frontend API client (api.ts) is the seam for real calls: apiFetch sends a session bearer token (falling back to a shared secret), but screens still use seeded data.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `npm run build` succeeds but deployment fails on type errors. | Run `npm run typecheck` (tsc --noEmit) and fix the errors; build does not typecheck. |
| `pytest` from backend/ cannot `import app`. | pytest.ini sets pythonpath=. so run pytest from the backend/ directory; ensure requirements are installed. |
| Browser blocks the SPA's API calls with a CORS error. | Set ALLOWED_ORIGINS (comma-separated) for the backend; it defaults to the Vite dev origins http://localhost:5173 and http://127.0.0.1:5173. |
| Backend fails to start because the configured database server is unreachable. | Leave DATABASE_URL unset to use the default local SQLite database, or start Postgres via docker compose and point DATABASE_URL at it (<database-connection-string>). |
| Playwright specs get collected by Vitest and fail. | Vitest is scoped to src/; keep Playwright specs under e2e/ and run them with npm run test:e2e. |
