<!-- sdlc:auto:start overview -->
MediBook is a two-application monorepo generated by the Quorq AI SDLC platform for a doctor appointment and consultation management product. `frontend/` is a Vite + React 19 single-page app (React Router 7, Tailwind 4, TypeScript) whose approved screens currently render seeded sample data; `src/lib/api.ts` is the prepared seam for real API calls. `backend/` is a FastAPI 0.115 service built on SQLAlchemy 2 and Pydantic 2 that, as generated, exposes only `GET /health` — `app/models.py` declares no tables and `app/routers/` holds no routers yet. The backend defaults to a local SQLite file (`sqlite:///./app.db`) so it starts with no database server, and creates tables from the models on startup via a FastAPI lifespan hook; `docker-compose.yml` provides PostgreSQL 16 and Redis 7 for when `DATABASE_URL` should point at a real server. A Dockerfile builds the API on python:3.12-slim and runs it with uvicorn on port 8000.
<!-- sdlc:auto:end overview -->

- Docker and Docker Compose (optional — only needed for the PostgreSQL 16 and Redis 7 services in docker-compose.yml)

<!-- sdlc:auto:start setup -->
1. Copy the example environment file at the repository root: cp .env.example .env
2. Install backend dependencies (a virtualenv at backend/.venv is what playwright.config.ts expects): cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt
3. Start the API (defaults to SQLite at backend/app.db, no database server needed): cd backend && .venv/bin/python -m uvicorn app.main:app --reload
4. Optional — start PostgreSQL 16 and Redis 7 instead: docker compose up -d, then export DATABASE_URL=postgresql+psycopg://app:app@localhost:5432/app before running uvicorn
5. Install frontend dependencies: cd frontend && npm install
6. Start the SPA dev server: cd frontend && npm run dev (Vite's default origin http://localhost:5173 is already allowed by the backend's CORS defaults)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Monorepo with two independently-run apps: frontend/ (npm) and backend/ (pip).
- Backend layering: main.py wires the app, database.py owns the engine/session, models.py the SQLAlchemy declarative Base, schemas.py the Pydantic request/response models, one router module per component in app/routers/.
- Database sessions come from the request-scoped get_db() dependency, one session per request, closed in a finally block.
- Configuration via environment variables with working defaults: DATABASE_URL (SQLite fallback), ALLOWED_ORIGINS (comma-separated, falls back to the Vite dev origins), VITE_API_BASE_URL, VITE_API_SECRET_KEY, E2E_BASE_URL.
- Schema is created from models at startup via the lifespan hook — no migrations ship; Alembic is the documented next step.
- Unimplemented endpoints return a typed StubResponse rather than raising, so the OpenAPI document stays complete.
- Frontend imports use the '@/' alias for src/ (configured in both vite.config.ts and tsconfig.json).
- Vitest component tests live beside the components they cover under src/**; Playwright specs stay in e2e/ and are excluded from Vitest's include glob.
- TypeScript is strict but with noImplicitAny and strictNullChecks disabled; build does not typecheck, so typecheck runs separately.
- Screens still render seeded sample data; src/lib/api.ts is the intended seam for wiring real endpoints.

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails with ModuleNotFoundError: No module named 'app'. | Run pytest from the backend/ directory — pytest.ini sets pythonpath = . so that `import app` resolves. |
| Browser calls from the SPA are blocked by CORS once the frontend is not on localhost:5173. | Set ALLOWED_ORIGINS to the frontend's origin (comma-separated list) before starting the backend; it defaults to http://localhost:5173 and http://127.0.0.1:5173. |
| `npm run build` succeeds but deployment/typecheck fails. | vite build does not typecheck. Run npm run typecheck (tsc --noEmit) and fix the reported errors — commonly untyped useState({}) read for named fields. |
| Playwright fails to start the API with a missing .venv/bin/python. | playwright.config.ts launches `cd ../backend && .venv/bin/python -m uvicorn app.main:app ...`. Create it first: cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt. |
| The frontend cannot reach the API. | src/lib/api.ts falls back to http://localhost:8000; start the backend there, or set VITE_API_BASE_URL at build time to the deployed API URL. |
| The app should use PostgreSQL but writes to a local app.db file. | DATABASE_URL defaults to sqlite:///./app.db. Run docker compose up -d and export DATABASE_URL pointing at the postgres service (user app, password app, database app, port 5432) before starting uvicorn. |
| docker compose fails because port 5432 or 6379 is already in use. | Stop the conflicting local PostgreSQL/Redis, or change the published port mapping in docker-compose.yml. |
| Expected business endpoints (doctors, appointments) return 404. | Only GET /health exists in this scaffold — app/routers/ is empty and app/models.py declares no tables. Add routers, models and schemas as features are implemented. |
