<!-- sdlc:auto:start overview -->
MediBook is a doctor appointment and consultation management system generated by the Quorq AI SDLC platform, living in one repository with two applications. The frontend (frontend/) is a Vite + React 19 single-page app using react-router-dom, @tanstack/react-query and react-hook-form; its screens were approved against a design and currently render seeded sample data, with src/lib/api.ts as the seam for wiring to the real API. The backend (backend/) is a FastAPI service (SQLAlchemy 2, Pydantic 2) exposing authentication, admin user management, clinic settings, specializations and catalogue, term-driven doctor search, the doctor directory, weekly availability and one-off exceptions, and an appointment booking surface that prevents double bookings. It defaults to a local SQLite database so a fresh clone runs with no database server, and points at PostgreSQL via DATABASE_URL when available. The system supports role-based access for patients, doctors and administrators, and uses deterministic disease/symptom-to-specialization table lookups (no AI/ML).

<!-- sdlc:auto:start setup -->
1. Clone the repository and open two terminals (one for frontend, one for backend).
2. Frontend: cd frontend
3. npm install
4. npm run dev
5. Backend: cd backend
6. pip install -r requirements.txt
7. uvicorn app.main:app --reload
8. Optional: from the repository root run 'docker compose up -d' to start PostgreSQL 16 and Redis 7, then set DATABASE_URL to point the backend at Postgres (otherwise the backend uses the default SQLite database at ./app.db).

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component that owns endpoints, wired together in app/main.py; routers are prefixed under /api (with admin endpoints under /api/admin).
- Pydantic schemas come in request/response pairs per entity and often accept alias field names (e.g. 'kind'/'entry_type', 'initial_password'/'password') for backward compatibility.
- Validation errors return 422 as {"detail": [{"field", "msg", ...}]}; forbidden/not-found that must be indistinguishable return 403/404 with an empty body (EmptyBodyHTTPError).
- Identity always comes from the verified bearer token, never the request body; roles are enforced via require_role dependencies.
- Passwords are stored only as bcrypt hashes; session tokens are stored only as a hash, with the raw token returned once at issuance.
- Soft-deactivation is preferred over hard deletion (is_active/profile_active/is_deleted) so appointment history and catalogue references are preserved.
- Database schema is created from models on startup (lifespan); SQLite is the default, Postgres is configured via DATABASE_URL.
- Frontend: screens live beside their tests in src/screens/; App.tsx holds the route table with role-guarded routes; API access goes through src/lib/api.ts (apiFetch/apiRequest) which sends a bearer token or shared secret and routes 401s to a registered handler.
- Vitest component tests are scoped to src/ while Playwright e2e specs live in e2e/; path alias '@' maps to ./src.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` from the backend directory fails with 'cannot import app'. | pytest.ini sets pythonpath=.; run pytest from the backend/ directory so the app package is importable. |
| Backend startup fails because DATABASE_URL names a server that is not running. | Leave DATABASE_URL unset to use the default SQLite database (sqlite:///./app.db), or start the db service via 'docker compose up -d' before pointing DATABASE_URL at Postgres. |
| Browser blocks the SPA's API calls with a CORS error. | The API allows the Vite/preview dev origins by default; for other origins set ALLOWED_ORIGINS (comma separated) for the backend. |
| `npm run build` succeeds but deployment fails on type errors. | `vite build` does not typecheck; run `npm run typecheck` (tsc --noEmit) and fix reported errors before relying on a build. |
| Startup rejects an invalid SESSION_IDLE_MINUTES value. | The value is validated at startup (validate_session_idle_minutes); set SESSION_IDLE_MINUTES to a valid value so the app boots instead of failing on every authenticated request. |
| Playwright e2e specs give inconsistent counts across runs. | The e2e setup creates a fresh SQLite database per run; run against a clean database (the config removes e2e.db before booting the backend) rather than reusing an accumulated one. |
<!-- sdlc:auto:end troubleshooting -->
