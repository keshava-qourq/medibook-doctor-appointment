# MediBook – Doctor Appointment & Consultation Management System

Develop a web-based healthcare appointment management application where patients can search for doctors based on their disease, symptoms, or medical specialization, view available doctors and their consultation time slots, and book, reschedule, or cancel appointments. Doctors can manage their availability, view scheduled appointments, maintain patient consultation records, and update consultation statuses. The system should support role-based access for patients, doctors, and administrators, with an admin dashboard to manage doctors, specializations, and appointments.

The application must use predefined disease-to-specialization mappings to help patients find relevant doctors, without using AI, LLMs, or machine learning. It should prevent double bookings and display real-time appointment availability. **No payment gateway or online payment functionality is required.**

Generated by the Quorq AI SDLC platform from an approved app design.

Every screen here was generated from a design the team reviewed and approved.
A backend was also generated for this project (see `../backend/`), but these
screens still run on **seeded sample data** -- wiring a given screen to a real
endpoint is the next job, not something this repository pretends to have done.

## Running it

```bash
npm install
npm run dev
```

`npm run build` bundles the app; it does not typecheck. The screens were generated, and a
generated screen that renders correctly can still not satisfy `tsc` -- usually an untyped
`useState({})` that is then read for named fields. Deployment would fail on that, which is
a poor reason not to ship a working prototype.

`npm run typecheck` runs `tsc --noEmit` when you want it, and is worth fixing before this
becomes a codebase anyone maintains.

## Checks and tests

- `npm run lint` / `npm run lint:fix` -- ESLint over the whole app; `lint:fix` applies the
  fixes it can. The platform runs `npm run lint` as a gate during development, so keep it green.
- `npm run test` -- Vitest component tests, beside the components they cover.
- `npm run test:e2e` -- Playwright acceptance tests from the `e2e/` folder beside `src/`.
  `npm run test:e2e:install` fetches the browser first. With `E2E_BASE_URL` set it runs against
  that deployed URL; without it, Playwright builds and serves this app and runs against that.

## Layout

- `src/App.tsx` -- the navigation shell and the route table.
